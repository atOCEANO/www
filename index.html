How the tools are built

  1. 01

    One job per repository

    Each repository does one thing and leaves the rest to the others.

  2. 02

    Decisions are written down

    Every design choice is recorded with its reason and its cost.

  3. 03

    Tested before every release

    A release ships only after its full test suite passes in a clean environment.

  4. 04

    A person approves every change

    Code may be written or reviewed with AI, but a person signs off before it is published.

  5. 05

    Breaking changes wait for a major version

    Each one arrives in a major release, with a migration guide.

  6. 06

    Docs change with the code

    A change in behaviour updates the documentation in the same release.
